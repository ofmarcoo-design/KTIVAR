# Revisão técnica de 17/10/2026

## Escopo

Código atual, dependências instaladas e lockfile, fontes oficiais de avisos,
APIs/autenticação, banco Supabase real (consultas agregadas e metadados),
regras de negócio, backup/restauração isolados, QR, PWA e interface responsiva.
A revisão preserva arquitetura, dados, domínio e layout do desktop.

## Correções desta revisão

- Health check reutiliza o cliente REST existente, com timeout e suporte a
  publishable keys. Respostas vazias/inválidas/offline não indicam sucesso.
  O horário representa a checagem atual; as respostas não são cacheadas.
- Requisições malformadas preservam status HTTP 400/413; erros inesperados
  de API não expõem mensagens internas.
- Cabeçalhos de segurança também cobrem rotas públicas/PWA; bloqueio de
  frames explícito e remoção do cabeçalho de identificação do Express.
- Busca de vendas filtra efetivamente cliente/empresa, mantendo período,
  situação e paginação. Itens inválidos e datas impossíveis são recusados.
- Perfis são construídos por completo antes da apresentação; respostas
  antigas não substituem um cliente/venda aberto mais recentemente.
- Nomes longos não comprimem o breadcrumb em letras verticais; o título
  do perfil no mobile é limitado a três linhas, mantendo o nome completo
  no conteúdo do cadastro.
- CI verifica npm audit e avisos revisados do GitHub independentemente.
  Falha de consulta não é reportada como ausência de avisos. Actions usam
  Node 24, commits fixos e checkout sem persistir credenciais.

## Verificações

- `npm run security`: auditoria npm de dependências diretas/transitivas e
  consulta oficial GitHub para versões fixas de express/qrcode/PGlite.
- `npm run build`: sintaxe de servidor, módulos, interface e scripts.
- `npm test`: migrations, estoque, vendas, CRM, RLS/IDOR, autenticação, CSRF,
  histórico/auditoria, backup/restauração, séries e sua capacidade, QR e
  respostas HTTP; inclui testes negativos de requisições inválidas.
- `scripts/verify-responsive.js`: 320/390/640/768/1440 e 844×390, contraste,
  teclado, menus, formulários, QR/download/NFC, CRUD e filtros, concorrência
  de respostas e zoom/reflow de 100% a 200%, com API isolada.
- QR rasterizado e decodificado a 224/300/1024 px: somente URL permanente.
- Banco real: todas as tabelas públicas com RLS; sem SECURITY DEFINER
  público; funções privilegiadas com search_path fixo; nenhum acesso
  anônimo a cadastros, séries, histórico ou dados financeiros.
  Acesso anônimo restringe-se ao health check e campos públicos de redirect.
- Consultas agregadas não encontraram séries inválidas/duplicadas, placas
  ativas sem vínculo/destino, itens de venda inválidos ou atividades de
  negociação pertencente a outro cliente. Nenhum dado real foi alterado.
- Busca heurística de segredos em 80 arquivos de texto versionados sem
  achados dos padrões de chaves privadas, tokens GitHub, AWS ou Supabase secret.

## Contexto do alerta Express

A versão 5.2.0 permanece fixada após a atualização solicitada.
O aviso GHSA-pj86-cfqh-vqx6 / CVE-2024-51999, citado nas notas dessa versão,
foi retirado em 02/12/2025: o mantenedor o classificou como bug de correção,
sem impacto real de segurança. Isso pode explicar divergências entre
scanners; a identificação completa usada pela Hostinger não ficou visível
no print. Avisos retirados não são tratados como vulnerabilidades ativas.

Fontes oficiais:
- https://github.com/advisories/GHSA-pj86-cfqh-vqx6
- https://github.com/expressjs/express/releases/tag/v5.2.0
- https://docs.github.com/en/rest/security-advisories/global-advisories
- https://supabase.com/docs/guides/database/joins-and-nesting
- https://supabase.com/changelog/cbc-tls-ciphers-deprecated

## Pendências e limites

- Supabase continua sinalizando proteção contra senhas vazadas desativada.
  Recurso disponível no plano Pro ou superior; não foi contratado plano
  nem alterado faturamento. https://supabase.com/docs/guides/auth/password-security
- Advisor de desempenho sinaliza índices ainda não usados (informativo);
  não foram removidos índices de integridade ou consulta por esse motivo.
- Express 5.3.0 e PGlite 0.5.10 estão disponíveis. Versão mais nova não é,
  por si só, prova de vulnerabilidade na versão fixada. PGlite é ferramenta
  de testes; não foi promovido a dependência de produção.
- Não houve acesso administrativo ao hPanel: versão efetiva do runtime,
  instalação no servidor e encerramento do alerta da Hostinger precisam
  de confirmação no painel após implantação/novo scan.
- Testes de escrita/ataque usam fixtures isoladas, sem alterações reais,
  carga agressiva ou força bruta contra produção. Não é um pentest externo,
  garantia de ausência de falhas desconhecidas ou cobertura de infraestrutura
  da Hostinger/Supabase. O worker PWA não intercepta nem armazena dados privados.
